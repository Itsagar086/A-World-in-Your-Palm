01 Section One

Executive summary

What was built, and the one constraint that shaped every decision in it.

A World in Your Palm is a browser game in which a small explorer walks around a complete spherical planet with eight distinct regions, each holding one interactive “small wonder” to wake up.

The defining constraint is that nothing is loaded. There is no art pipeline, no .glb, no texture atlas, no .mp3. Every tree, cottage, coral, character limb, footstep and chime is generated by JavaScript at page load. The entire shippable product is one HTML file you could email to someone.

That constraint drives the architecture. Because props are functions, they can be authored as deep hierarchies of hundreds of tiny meshes — the only sane way to write a windmill by hand — and then mechanically flattened before rendering.

The headline result. 6,348 meshes authored in code collapse into 213 merged batches — a 96.6% reduction in draw work with no loss of visual detail. That single function is what makes the approach viable.

02 Section Two & Three

The brief, and how the reference was read

What was asked, how it was interpreted, and what static analysis recovered from a 916 KB minified file.

2. The brief

“Go through the link like a tester, gamer, senior game developer with 40+ years of experience. Understand the game, don’t leave any single part of it, including the map assets, everything. Now develop exactly the same kind of thing from the observed analysis — just change some small wonder tasks and names, add some extra features, but build it in a similar way, like a pro.”

The reference was a published demo, Little Planet — A Pocket Adventure. The instruction was explicitly not “copy the file” — it was understand it, then build your own to the same standard. That framed the work in three phases.

PhaseGoal
1 — AnalysisDissect the reference down to its algorithms, not its pixels
2 — DesignRe-theme all content; decide what to add beyond the reference
3 — BuildImplement from scratch, verify empirically, ship

Interpretation decisions

  • “Everything, including map assets” — the reference has no asset files, so “assets” meant the procedural generators that produce them. Analysis had to reach the generator level, not the screenshot level.
  • “Change names and some wonder tasks” — all eight regions renamed and all eight wonders redesigned with new mechanics, not new labels.
  • “Like a pro” — a real project structure with a build step, a test harness and documentation, rather than one 900 KB file.

3. Reverse-engineering the reference

The reference ships as a single 916 KB HTML file: a minified Three.js bundle plus roughly 133 KB of minified game code. It was analysed statically.

1. Fetch the page source                →  916 KB, 4,545 lines
2. Locate <script> boundaries          →  one giant IIFE
3. Split vendor bundle from game code   →  isolated at offset ~760 KB
4. Index every top-level declaration    →  ~200 minified symbols mapped
5. Read each subsystem, renaming as understood

Minified identifiers were reconstructed by reading their bodies and inferring intent. For example jd(s,t,e) turned out to be a closed-form great-circle-arc versus spherical-cap intersection test.

Reference symbolWhat it actually is

Kd(p)Terrain radius = blended per-biome elevation + detail octaves
Je(root)The geometry baker — transform folding + colour-to-vertex-colour
jd(a,b,caps)Closed-form arc-versus-cap visibility test

The five ideas worth keeping

Analysis concluded that the demo’s quality comes from five decisions, all of which were adopted and independently re-implemented.

  1. Props are code, not data. Removes the entire asset pipeline.
  2. Author deep, then bake. Deep hierarchies for authoring; flat merged geometry for rendering.
  3. Position is a unit normal, not a point. The character is glued to a sphere by construction, so “fell through the world” cannot happen.
  4. Obstacles are spherical caps. Blocking becomes a dot product; visibility becomes one atan2.
  5. Synthesise the audio. Per-material footsteps for free.

Everything else — layout, content, palette, features — was designed fresh.

6. Architecture

Eleven files load in numeric order as classic scripts. Each is an IIFE that attaches one namespace to a global TW object. Load order is the dependency order — a module can only use what is already defined above it.

ModuleDepends on
TW.core— (only Three.js)
TW.natureTW.core
TW.propsTW.core, TW.nature
TW.biomesTW.core, TW.nature, TW.props
TW.planetTW.core, TW.nature, TW.biomes
TW.walk— (only Three.js)
TW.explorerTW.core, TW.walk
TW.audio— (only Web Audio)
TW.renderTW.core
TW.appcore, planet, walk, render, explorer, audio

The graph is acyclic with one deliberate inversion: TW.planet calls TW.biomes.buildAll(ctx) and hands it a context object, while the biome files call back into ctx.place(), ctx.path() and ctx.wonder(). Content does not know about spheres; the planet does not know about content.

Why no bundler. Classic script tags load from file:// without a server, without CORS problems, and without a toolchain. The cost is manual load ordering and no tree-shaking; the benefit is that a contributor can edit a file, press reload, and see the change. build.mjs recovers the single-file distribution when one is wanted.
07 Section Seven

The engine, system by system

The primitive kit, world generation, spherical motion, navigation, the character, rendering and audio.

7.1  The primitive kit and the baker

Six primitives build the entire world.

FunctionProduces
box(p, x,y,z, w,h,d, col)Axis-aligned box
rock(p, …, coarse)Randomly tumbled icosahedron — every boulder, bush and blob
cone(p, …, rBot, h, seg, rTop)Tapered cylinder; rTop = 0 gives a cone
tube(…)cone with equal radii
link(p, a, b, r, col)A cylinder between two points — ropes, branches, struts
poly(verts, faces, colors)Raw triangle soup for anything bespoke

bake() — the load-bearing function

For every static, opaque, single-material mesh under a root:

  1. Fold the world transform into the vertex positions.
  2. Fold the flat material colour into a vertex-colour attribute, and swap in a shared white vertexColors material. This is the trick — it lets meshes of different colours merge into one geometry.
  3. Concatenate into one buffer per (material, castShadow, receiveShadow) bucket.

Anything marked userData.dynamic — and its whole subtree — is skipped, so animated joints keep their own transforms.

Authored6,348meshes
Merged into213batches
Groups pruned2,217empty husks

Determinism. rand(a,b) is a seeded LCG. Nothing in generation may call Math.random(), so the planet is byte-identical on every machine and in every screenshot.

7.2  Generating a world

Eight biome centres are placed by latitude and longitude. Any point on the sphere belongs to the nearest centre — but the distance metric is perturbed:

score = dot(centre, p) + 0.018 · sin(p.x·9 + i·2.3) · sin(p.y·8 − p.z·6 + i·0.6)

Without the noise term the borders would be clean great-circle arcs and look manufactured. classify() also returns the runner-up and the margin, which lets elevation blend across a border instead of forming a cliff.

The terrain mesh is IcosahedronGeometry(14, 40) — 100,860 vertices. Each face is displaced, classified, and given a per-face colour with a small random tint. Flat-shaded, so the facets are the aesthetic.

The placement context

Biome files never touch spheres. They receive:

7.3  Walking on a sphere

The explorer has no position. It has a unit normal — the direction from the planet centre to its feet — and a unit tangent forward. Moving is rotating the normal along a great circle:

advance(from, dir, distance, radius):
    t = tangent(dir, from)
    a = distance / radius
    return from·cos(a) + t·sin(a)      // normalised

Height comes from surfaceRadius(normal), so the character is welded to the terrain by construction. There is no gravity solve and no ground raycast. After each move the facing vectors are parallel-transported along the step with a quaternion built from the before/after normals, so they stay tangent without drift.

Obstacles are spherical caps. Being inside one is dot(p, cap.normal) > cos(angularRadius). resolve() pushes a point back out along the tangent, three iterations, every frame.

7.4  Navigation

Along the great circle from a to b, the dot product with a cap centre is:

f(t) = h·cos t + d·sin t  =  R·cos(t − φ)     where R = hypot(h,d), φ = atan2(d,h)

So the closest approach to any obstacle is one atan2 — no marching, no sampling. This is what makes planet-scale A* cheap enough to run inside a click handler.

StageDetail
GraphIcosahedronGeometry(1, 21) deduplicated to 4,842 nodes. Nodes inside an obstacle are closed; edges survive only if the arc between them is clear
CachingBuilt once, cached on the collider array via a WeakMap, and pre-warmed at load so the first click never pays the ~76 ms cost
SearchA* with a great-circle heuristic and a binary heap, using a virtual goal node so multiple entry portals relax cheaply
SmoothingString-pulling: from each anchor, skip to the furthest waypoint still in clear line of sight. A staircase becomes 2–5 long natural legs
Two-tier design, verified. If A* returns null — for instance if the walker is standing inside a cap — the walker falls back to reactive steering: head toward the target, and when an obstacle is in the way, commit to one side and slide. Measured: from a blocked start with _route === null, the walker escaped the cap and covered 10.9 m in 2 simulated seconds.

7.5  The character

A real skeleton of nested pivots — no skinning and no animation data.

root
└── body                       whole-body bob, lean, roll
    ├── torso                  coat, pockets, straps, chest compass
    │   └── pack               bedroll, mug, map, buckles
    ├── legL / legR
    │   └── thigh → knee → ankle
    ├── armL / armR
    │   └── shoulder → elbow → hand
    │       └── lantern        left hand — swings, lights at dusk
    └── head
        ├── eyes ×2            blink on a 5.4 s cycle
        ├── hat                brim, seams, goggles on the crown
        └── scarf → tail       trails with movement

The walk cycle is a handful of sines driven by distance travelled, not wall time — so the gait always matches the speed. Five blend weights chase their targets exponentially and layer poses on top of each other. Each joint is baked individually with keepRootLive, so a joint’s own static meshes merge while its children stay independently animatable.

The companion owns a full Walker — it pathfinds around obstacles exactly as the player does, follows when the gap exceeds 2.4 m, and sits down when it closes to 1.3 m.

7.6  Lighting and the post chain

The sun runs on a clean tilted great circle, sunDir(t) = A·cos 2πt + B·sin 2πt. Keeping it analytic is what makes the held sky settings work: since dot(n, sunDir(t)) = R·cos(2πt − φ), the time that produces a given sun elevation at a given point is one acos.

solveTimeFor(normal, target):
    a = normal·A ; b = normal·B
    R = hypot(a, b) ; φ = atan2(b, a)
    return (φ + acos(clamp(target / R, −1, 1))) / 2π

A full day is 420 s. Local daylight is clamp(dot(normal, sunDir)·2.6 + 0.42, 0, 1) and drives ambient level and colour, hemisphere light, moon fill, star opacity, atmosphere tint, the night colour grade, and the lantern.

Explorer occlusion. Props between the camera and the explorer dither away using a fixed 4×4 Bayer pattern, injected into every opaque standard material via onBeforeCompile. Fixed rather than noise — a noise pattern sparkles when you stand still.

Graceful degradation. Without WebGL 2 the whole chain is replaced by a direct render with ACES tone mapping. Below 40 fps the pixel ratio drops; below that again, bloom and soft shadows are dropped.

7.7  The synthesiser

No audio files. Voices are built per event and self-dispose via onended.

SoundConstruction
FootstepBand-limited noise burst (lowpass sweep + highpass) + low sine “thud”
SplashLonger, brighter burst with a higher highpass
WindOne looping brown-noise buffer through a lowpass whose corner follows the region
DiscoveryPentatonic tone, one note per region — nothing can sound wrong
RoomSynthetic impulse response through a ConvolverNode

Per-region ground profiles tune filter cutoff, duration, level and thud pitch — sand is long and bright (2600 Hz, 145 ms), volcanic rock is short and hard (3400 Hz, 45 ms).

11. Testing and verification

The game is verified by driving the real build in a real browser. Two deliberate hooks make that possible: an <output id="telemetry"> element carrying full runtime state as JSON, and a TW.app namespace with live handles to the renderer, scene, walker, world and lighting.

A lesson worth recording. The harness first read everything from telemetry and produced false failures. Telemetry refreshes on the simulation clock, which crawls under software rasterisation. Anything time-sensitive must read live state through TW.app; telemetry is for the human-facing summary and for checking that the channel itself works.

15 Section Fifteen & Sixteen

Studying and extending the project

A reading order that builds understanding, and the rules for adding to it.

15. How to study this project

Session 1 — the idea  1 hour

  1. Play it. Find all eight wonders. Press N at Lalbagh Hollow.
  2. Read src/00-core.js top to bottom. It is the smallest file and everything else is built from it.
  3. In the browser console: TW.core.bake.totalMerged → 6348, TW.core.bake.totalBatches → 213.

Session 2 — how a world gets made  2 hours

  1. Read TW.nature.pine and TW.props.cottage. They are just functions returning groups.
  2. Read ctx in src/30-planet.js — the boundary between engine and content.
  3. Read one region builder in src/40-biomes-a.js. It reads like a planting list.
  4. Change a colour, save, reload. That loop is the whole point of the no-bundler decision.

Session 3 — the mathematics  2 hours

  1. Read src/50-walker.js. Take arcIsClear() slowly — write out f(t) = R·cos(t − φ) on paper.
  2. Plan a route from the console and inspect the waypoints.
  3. Read solveTimeFor() in src/80-render.js — the same trick applied to sunlight.

Session 4 — presentation  2 hours

  1. Read createExplorer(). Set moveBlend by hand and watch the pose change.
  2. Read createPost() and follow one pixel through the chain.
  3. Read frame() in src/90-app.js — the whole game in one function.

Live experiments

TW.app.lighting.setPhase('night');       // hold the sky
TW.app.walker.walkSpeed = 8;             // sprint
TW.app.post.bloomEnabled = false;        // A/B the bloom

Internal IDs remain the original development names — mosswood, cinderpeak — because they are the keys existing save files were written with. Only the display names changed.

16. Extending the game

Add a prop

// in src/20-props.js
P.watchtower = function (parent, x, z, height) {
  var g = C.group(parent, x, 0, z);
  for (var s = -1; s <= 1; s += 2)
    for (var t = -1; t <= 1; t += 2)
      C.link(g, [s*0.4, 0, t*0.4], [s*0.22, height, t*0.22], 0.05, PAL.wood);
  C.box(g, 0, height, 0, 0.7, 0.06, 0.7, PAL.wood);
  P.gableRoof(g, 0.8, 0.8, height + 0.5, height + 0.9, PAL.roofRed);
  return g;
};

It bakes automatically. Use it with ctx.place('mosswood', 2, -1, g => P.watchtower(g, 0, 0, 1.8)).

Add a region

  1. Append an entry to BIOMES in src/30-planet.js — pick a lat/lon well clear of the others.
  2. Add region-specific shaping in regionElevation() if wanted.
  3. Push a builder onto B.list in a biome file.
  4. Add a footstep profile to GROUND in src/70-audio.js.

Rules to respect

RuleWhy
Never call Math.random() during generationUse ctx.rand() — the world must be deterministic
Anything animated needs C.dyn() or C.pivot()Otherwise bake() will merge it and freeze it
Long props need multiple anchors, or ctx.path()One anchor over a slope hovers at the far end (bugs 5 and 6)
Register a collider for anything solidctx.block(id, x, z, radius)
Run node build.mjs after editingOtherwise dist/ goes stale
