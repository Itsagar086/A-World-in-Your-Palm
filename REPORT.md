## 1. Executive summary

*A World in Your Palm* is a browser game in which a small explorer walks around a
complete spherical planet with eight distinct regions, each holding one
interactive "small wonder" to wake up.

The defining constraint is that **nothing is loaded**. There is no art pipeline,
no `.glb`, no texture atlas, no `.mp3`. Every tree, cottage, coral, character
limb, footstep and chime is generated by JavaScript at page load. The entire
shippable product is one HTML file you can email to someone.

That constraint drives the architecture. Because props are *functions*, they can
be authored as deep hierarchies of hundreds of tiny meshes — the only sane way
to write a windmill by hand — and then mechanically flattened before rendering.
**6,348 authored meshes collapse into 213 merged batches**, a 96.6% reduction,
with no loss of visual detail.

## 2. The brief

> *"Go through the link like a tester, gamer, senior game developer with 40+ years
> of experience. Understand the game, don't leave any single part of it, including
> the map assets, everything. Now develop exactly the same kind of thing from the
> observed analysis — just change some small wonder tasks and names, add some extra
> features, but build it in a similar way, like a pro."*

The reference was a published demo: *Little Planet — A Pocket Adventure*. The
instruction was explicitly **not** "copy the file" — it was *understand it, then
build your own to the same standard*.

That framed the work in three phases:

| Phase | Goal |
|---|---|
| **1 — Analysis** | Dissect the reference down to its algorithms, not its pixels |
| **2 — Design** | Re-theme content; decide what to add beyond the reference |
| **3 — Build** | Implement from scratch, verify empirically, ship |

### Interpretation decisions

- **"Everything, including map assets"** → the reference has no asset files, so
  "assets" meant *the procedural generators that produce them*. Analysis had to
  reach the generator level, not the screenshot level.
- **"Change names and some wonder tasks"** → all eight regions renamed and all
  eight wonders redesigned with new mechanics, not just new labels.
- **"Add extra features"** → six additions the reference does not have
  (§4.3).
- **"Like a pro"** → a real project structure with a build step, a test harness
  and documentation, rather than one 900 KB file.

## 3. Phase 1 — Reverse-engineering the reference

The reference ships as a single 916 KB HTML file: a minified Three.js bundle plus
roughly 133 KB of minified game code. It was analysed statically — downloaded,
split, and read.

### 3.1 Method

```
1. Fetch the page source                        →  916 KB, 4,545 lines
2. Locate <script> boundaries                   →  one giant IIFE
3. Split vendor bundle from game code           →  game code isolated at offset ~760 KB
4. Index every top-level declaration            →  ~200 minified symbols mapped
5. Read each subsystem, renaming as understood   →  algorithms recovered
```

Minified identifiers (`Un`, `Kd`, `jd`, `D3`) were reconstructed by reading their
bodies and inferring intent — for example `jd(s,t,e)` turned out to be a
closed-form great-circle-arc versus spherical-cap intersection test.

### 3.2 What the analysis recovered

| Reference symbol | What it actually is |
|---|---|
| `Un = 14`, `Jd = Un + .025` | Planet radius and sea level |
| `ux(p)` | Nearest-biome classification with sinusoidal border noise |
| `Kd(p)` | Terrain radius = blended per-biome elevation + detail octaves |
| `Je(root)` | The geometry baker — transform folding + colour-to-vertex-colour |
| `jd(a, b, caps)` | Closed-form arc-vs-cap visibility test |
| `D3(from, to, …)` | A* over a geodesic graph + string-pulling |
| `Qd` class | The spherical walker |
| `vx()` | Procedural character rig |
| `Sx()` | WebAudio synthesiser with per-biome footstep profiles |
| `B3` / Bayer chunk | Dithered occlusion of props in front of the camera |

### 3.3 The five ideas worth keeping

Analysis concluded that the demo's quality comes from five decisions, all of
which were adopted (and independently re-implemented):

1. **Props are code, not data.** Removes the entire asset pipeline.
2. **Author deep, then bake.** Deep hierarchies for authoring; flat merged
   geometry for rendering.
3. **Position is a unit normal, not a point.** The character is glued to a
   sphere by construction, so "fell through the world" cannot happen.
4. **Obstacles are spherical caps.** Blocking becomes a dot product; visibility
   becomes one `atan2`.
5. **Synthesise the audio.** Per-material footsteps for free; zero download.

Everything else — layout, content, palette, features — was designed fresh.

## 4. Phase 2 — Design decisions

### 4.1 The eight regions

Named in English with a deliberate Indian sense of place.

| # | Terrain | Region | Character |
|---|---|---|---|
| 01 | Forest | **Cubbon Woods** | Starting camp, treehouse, stream, waterfall |
| 02 | Meadow | **Hesaraghatta Fields** | Farm, barn, crop rows, beehives, scarecrow |
| 03 | Desert | **Ramanagara Dunes** | Ruined arch, caravan camp, cacti, bones |
| 04 | Coast | **Ulsoor Bay** | Stilt huts, jetty, beached boat, shells |
| 05 | Reef | **Sankey Deep** | Fully submerged — corals, kelp, a shipwreck |
| 06 | Volcano | **Savandurga Peak** | Live crater, lava flows, research station |
| 07 | Tundra | **Nandi Frost** | Igloo, sled, frozen lake, aurora |
| 08 | Hollow | **Lalbagh Hollow** | Giant glowing fungus, stone circle |

### 4.2 The eight wonders

Each is a toggle that changes the region's state, returns a line of prose, and is
replayed on load so the world resumes as you left it.

| Region | Action | Effect |
|---|---|---|
| Cubbon Woods | Light the camp | Campfire, three lamp posts, treehouse string lights, 34 fireflies |
| Hesaraghatta Fields | Start the windmill | Sails accelerate, 20 bees emerge, 22 flowerbeds bloom |
| Ramanagara Dunes | Turn the dial | A hidden oasis scales up from nothing — pool, palms, butterfly |
| Ulsoor Bay | Ring the bell | Bell swings; a sailboat sails a full circuit of the cove and returns |
| Sankey Deep | Wake the reef | Every coral material lights at once; a 16-fish school appears |
| Savandurga Peak | Read the instruments | All lava materials brighten and pulse; dish and telescope track |
| Nandi Frost | Ring the chime | Three aurora curtains unroll across the polar sky |
| Lalbagh Hollow | Open the jars | Nine jars and every glowing surface rise; 70 motes swarm |

### 4.3 Six additions beyond the reference

| Addition | Why |
|---|---|
| **An eighth region** | The reference has seven; a night-themed region justified the bloom pipeline |
| **Real day/night cycle** | A directional sun on a tilted orbit — half the globe is genuinely dark and you can *walk* across the terminator |
| **Carried lantern with a point light** | Auto-lights at dusk and casts an actual pool of light — makes the night side worth visiting rather than merely survivable |
| **Companion creature** | Follows with its own spherical walker and pathfinding, so it never clips through trees |
| **16 collectible wisps** | A secondary exploration loop independent of the wonders |
| **Compass + photo mode** | Wayfinding, and a PNG export for sharing |

### 4.4 A design decision worth defending

The held sky settings (**day / dusk / night**) do not pin a clock time. They
solve for the sun position that produces that sky **at the explorer's current
location**, and keep re-solving as you walk. On a planet you can circumnavigate,
"night" pinned to a clock would mean broad daylight wherever you happened to be
standing. This is handled analytically — see §7.6.

## 6. Architecture

### 6.1 Module map and load order

Eleven files load in numeric order as classic scripts. Each is an IIFE that
attaches one namespace to a global `TW` object. Load order **is** the dependency
order — a module can only use what is already defined above it.

```
                       vendor/three.min.js   →  window.THREE
                                 │
   ┌─────────────────────────────┼─────────────────────────────┐
   │                                                            │
00-core.js      TW.core       primitives, materials, bake()
   │                             ▲        ▲          ▲
10-nature.js    TW.nature ───────┘        │          │   trees, animals, water, fire
   │                ▲                     │          │
20-props.js     TW.props ─────────────────┘          │   buildings, machinery, boats
   │                ▲                                │
30-planet.js    TW.planet ───────────────────────────┘   terrain, regions, placement
   │                ▲
40/41-biomes    TW.biomes                              the eight authored regions
   │
50-walker.js    TW.walk                                spherical motion + A*
   │
60-explorer.js  TW.explorer                            character rig, companion
   │
70-audio.js     TW.audio                               synthesiser
   │
80-render.js    TW.render                              lighting, day/night, post
   │
90-app.js       TW.app                                 input, cameras, HUD, loop
```

### 6.2 Measured dependency edges

Extracted from the source, not asserted:

| Module | Depends on |
|---|---|
| `TW.core` | — (only Three.js) |
| `TW.nature` | `TW.core` |
| `TW.props` | `TW.core`, `TW.nature` |
| `TW.biomes` | `TW.core`, `TW.nature`, `TW.props` |
| `TW.planet` | `TW.core`, `TW.nature`, `TW.biomes` |
| `TW.walk` | — (only Three.js) |
| `TW.explorer` | `TW.core`, `TW.walk` |
| `TW.audio` | — (only Web Audio) |
| `TW.render` | `TW.core` (shader patching) |
| `TW.app` | `TW.core`, `TW.planet`, `TW.walk`, `TW.render`, `TW.explorer`, `TW.audio` |

The graph is acyclic with one deliberate inversion: `TW.planet` calls
`TW.biomes.buildAll(ctx)` and hands it a context object, while the biome files
call back into `ctx.place()`, `ctx.path()` and `ctx.wonder()`. Content does not
know about spheres; the planet does not know about content.

### 6.3 Why no bundler

A conscious trade. Classic `<script src>` tags load from `file://` without a
server, without CORS problems, and without a toolchain. The cost is manual load
ordering and no tree-shaking; the benefit is that a contributor can edit
`src/30-planet.js`, press reload, and see the change. `build.mjs` recovers the
single-file distribution when one is wanted.

## 7. The engine, system by system

### 7.1 `00-core.js` — the primitive kit and the baker

**Six primitives build the entire world:**

| Function | Produces |
|---|---|
| `box(parent, x,y,z, w,h,d, color)` | Axis-aligned box |
| `rock(parent, …, coarse)` | Randomly tumbled icosahedron — every boulder, bush and blob |
| `cone(parent, …, rBottom, height, segments, rTop)` | Tapered cylinder; `rTop = 0` gives a cone |
| `tube(…)` | `cone` with equal radii |
| `link(parent, a, b, radius, color)` | A cylinder *between two points* — ropes, branches, struts |
| `poly(verts, faces, colors)` | Raw triangle soup for anything bespoke |

Plus `slab()` (extruded 2D outline), `ribbon()` (swept variable-width strip),
`torus()`, `sphere()`, and `beam()` (a box between two points).

**Determinism.** `rand(a, b)` is a seeded LCG. Nothing in generation may call
`Math.random()`, so the planet is byte-identical on every machine and in every
screenshot.

**Material deduplication.** `mat(color, opts)` caches on
`colour + JSON.stringify(opts)`. Tens of thousands of meshes end up sharing a few
dozen material instances — the precondition for aggressive merging.

**`bake(root, keepRootLive)` — the load-bearing function.**

For every static, opaque, single-material mesh under `root`:

1. Fold the world transform into the vertex positions.
2. Fold the flat material colour into a **vertex-colour attribute**, and swap in
   a shared white `vertexColors: true` material. *This is the trick* — it lets
   meshes of different colours merge into one geometry.
3. Concatenate into one buffer per `(material, castShadow, receiveShadow)` bucket.

Anything marked `userData.dynamic` — and its whole subtree — is skipped, so
animated joints keep their own transforms. `dyn(object, fn)` sets that flag and
registers a per-frame callback.

> **Result:** 6,348 authored meshes → 213 batches. The single most valuable
> function in the codebase.

### 7.2 `30-planet.js` — generating a world

**Region classification.** Eight biome centres are placed by latitude/longitude.
Any point on the sphere belongs to the nearest centre — but the distance metric
is perturbed:

```js
score = dot(centre, p) + 0.018 · sin(p.x·9 + i·2.3) · sin(p.y·8 − p.z·6 + i·0.6)
```

Without the noise term the borders would be clean great-circle arcs and look
manufactured. `classify()` also returns the runner-up and the margin, which lets
elevation blend across a border instead of forming a cliff.

**Elevation.** Per-region base elevation, plus region-specific shaping —
a shelving beach, sine dunes, a volcanic cone with a *flattened* crater floor,
a bowl ringed by hills — plus three octaves of detail noise. `surfaceRadius()`
clamps to sea level so the seas are swimmable rather than fatal.

**The terrain mesh.** `IcosahedronGeometry(14, 40)` — 100,860 vertices. Each
face is displaced, classified, and given a per-face colour with a small random
tint. Flat-shaded, so the facets are the aesthetic.

**The placement context.** Biome files never touch spheres. They receive:

| API | Purpose |
|---|---|
| `ctx.place(id, x, z, build, opts)` | Drop a prop at local metres; handles the tangent frame |
| `ctx.path(id, points, width, color)` | Drape a footpath over the terrain |
| `ctx.block(id, x, z, radius)` | Register a collision cap |
| `ctx.wonder(spec)` | Register an interactive landmark |
| `ctx.wisp(id, x, z)` | Register a collectible |
| `ctx.sky(build)` | A group whose local frame *is* world space (used by the aurora) |
| `ctx.tick(fn)` | Per-frame callback outside the prop hierarchy |

**Broadcast scatter.** 1,650 Fibonacci-sphere points fill the space *between*
authored set pieces with region-appropriate filler, skipping anything too close
to a region centre or an existing collider.

### 7.3 `50-walker.js` (part 1) — walking on a sphere

**The explorer has no position.** It has:

- `normal` — a unit vector from the planet centre to its feet
- `forward` — a unit tangent

Moving is rotating `normal` along a great circle:

```js
advance(from, dir, distance, radius):
    t = tangent(dir, from)
    a = distance / radius
    return from·cos(a) + t·sin(a)      // normalised
```

Height comes from `surfaceRadius(normal)`, so the character is welded to the
terrain by construction. There is no gravity solve and no ground raycast.

After each move, the facing vectors are **parallel-transported** along the step
with a quaternion built from the before/after normals, so they stay tangent
without drift.

**Collision.** Obstacles are spherical caps `{normal, radius}`. Being inside one
is `dot(p, cap.normal) > cos(angularRadius)`. `resolve()` pushes a point back out
along the tangent away from the centre, three iterations, every frame.

### 7.4 `50-walker.js` (part 2) — navigation

**The closed-form visibility test.** Along the great circle from `a` to `b`, the
dot product with a cap centre is:

```
f(t) = h·cos t + d·sin t  =  R·cos(t − φ)      where R = hypot(h, d), φ = atan2(d, h)
```

So the closest approach to any obstacle is **one `atan2`** — no marching, no
sampling. This is what makes planet-scale A* cheap enough to run inside a click
handler. There is also a cheap midpoint rejection that skips caps the arc cannot
possibly reach.

**The graph.** `IcosahedronGeometry(1, 21)` deduplicated to **4,842 nodes**
covering the whole globe. Nodes inside an obstacle are closed; edges between
neighbours survive only if the arc between them is clear. Built once, cached on
the collider array via a `WeakMap`, and **pre-warmed at load** so the first
click never pays the ~76 ms construction cost.

**Planning.** A* with a great-circle-distance heuristic and a binary heap, using
a virtual goal node so multiple entry portals can be relaxed cheaply. Then
**string-pulling**: from each anchor, skip to the furthest waypoint still in
clear line of sight. A staircase of graph hops becomes 2–5 long natural legs.

**Two-tier design, verified.** If A* returns `null` — for instance if the walker
is standing inside a cap — the walker falls back to reactive steering:
head toward the target, and when an obstacle is in the way, commit to one side
and slide. Measured: from a blocked start with `_route === null`, the walker
escaped the cap and covered **10.9 m in 2 simulated seconds**.

### 7.5 `60-explorer.js` — the character

A real skeleton of nested pivots:

```
root
└── body                          whole-body bob, lean, roll
    ├── torso                     coat, pockets, straps, chest compass
    │   └── pack                  bedroll, mug, map, buckles
    ├── legL / legR
    │   └── thigh → knee → ankle
    ├── armL / armR
    │   └── shoulder → elbow → hand
    │       └── lantern           (left hand — swings, lights at dusk)
    └── head
        ├── eyes ×2               blink on a 5.4 s cycle
        ├── hat                   brim, seams, goggles on the crown
        └── scarf → tail          trails with movement
```

**No skinning, no animation data.** The walk cycle is a handful of sines driven
by *distance travelled*, not wall time — so the gait always matches the speed.
Five blend weights (`moveBlend`, `swimBlend`, `airBlend`, `waveBlend`, plus a
run flag) chase their targets exponentially and layer poses on top of each other.

Each joint is `bake()`d individually with `keepRootLive = true`, so a joint's own
static meshes merge while its children stay independently animatable.

`createCompanion()` builds a second creature that owns a **full `Walker`** — it
pathfinds around obstacles exactly as the player does, follows when the gap
exceeds 2.4 m, and sits down when it closes to 1.3 m.

### 7.6 `80-render.js` — lighting and the post chain

**The sun runs on a clean tilted great circle:**

```js
sunDir(t) = A·cos(2πt) + B·sin(2πt)          // A, B orthonormal
```

Keeping it analytic is what makes the held sky settings work. Since
`dot(n, sunDir(t)) = R·cos(2πt − φ)`, the time that produces a given sun
elevation at a given point is **one `acos`**:

```js
solveTimeFor(normal, target):
    a = normal·A ; b = normal·B
    R = hypot(a, b) ; φ = atan2(b, a)
    return (φ + acos(clamp(target / R, −1, 1))) / 2π
```

A full day is 420 s. Local daylight is `clamp(dot(normal, sunDir)·2.6 + 0.42, 0, 1)`
and drives ambient level and colour, hemisphere light, moon fill, star opacity,
atmosphere tint, the night colour grade, and the lantern.

**The post chain** — hand-written, no addons:

```
scene ──► HDR half-float target (4× MSAA)
            │
            ├─► bright pass (soft-knee threshold) ──► ½-res
            │        └─► blur H → blur V → blur H(×2.4) → blur V(×2.4)
            │
            └─► composite:  scene + bloom
                            × exposure
                            night colour grade
                            Khronos PBR Neutral tone map
                            vignette
                            sRGB encode
                            premultiplied alpha ──► screen
```

The composite carries the scene's own coverage into the output alpha, so the CSS
page gradient shows around the planet instead of a black rectangle.

**Explorer occlusion.** Props between the camera and the explorer dither away
using a fixed 4×4 Bayer pattern, injected into every opaque standard material via
`onBeforeCompile`. Fixed rather than noise — a noise pattern sparkles when you
stand still.

**Graceful degradation.** Without WebGL 2 the whole chain is replaced by a direct
`renderer.render()` with ACES tone mapping. Below 40 fps the pixel ratio drops;
below that again, bloom and soft shadows are dropped.

### 7.7 `70-audio.js` — the synthesiser

No audio files. Voices are built per event and self-dispose via `onended`.

| Sound | Construction |
|---|---|
| Footstep | Band-limited noise burst (lowpass sweep + highpass) + low sine "thud" |
| Splash | Longer, brighter burst with a higher highpass |
| Wind | One looping brown-noise buffer through a lowpass whose corner follows the region |
| Discovery | Pentatonic tone, one note per region — nothing can sound wrong |
| Fanfare | Four-note arpeggio + sub-bass, on completing all eight |
| Room | Synthetic impulse response through a `ConvolverNode` |

Per-region ground profiles tune filter cutoff, duration, level and thud pitch —
sand is long and bright (2600 Hz, 145 ms), volcanic rock is short and hard
(3400 Hz, 45 ms).

The whole engine is defensive: a `panic()` path silences and suspends everything
on any exception, it parks the `AudioContext` when silent, respects tab
visibility, and only starts inside a user gesture as browsers require.

### 7.8 `90-app.js` — the application layer

Owns the renderer, both cameras, input, HUD, persistence and the frame loop.

**Two camera modes.** *Globe* orbits the planet in spherical coordinates and
auto-rotates after 14 s idle. *Follow* orbits the explorer with `camera.up`
lerped to the surface normal. Both ease exponentially.

**Movement is camera-relative.** Each frame, the camera's world X and Y axes are
projected into the tangent plane at the explorer's feet and handed to the walker
as `right` and `forward`. "Forward" always means "away from the camera",
whichever way the planet is turned.

**Persistence.** Wonder IDs, wisp IDs and distance walked go to `localStorage`.
On load, completed wonders have `activate()` replayed so the world resumes in the
state you left it.

**Telemetry.** Full runtime state is published as JSON into a screen-reader-only
`<output id="telemetry">` — the hook the automated harness reads.


### 8.2 Per-frame flow

```
frame(now)
   │
   ├─ camera.matrixWorld ─► cameraRight / cameraUp ─► TW.walk.tangent()
   │
   ├─ walker.update(dt, {x, y, forward, right, running})
   │     ├─ _steer()              ← only when auto-walking
   │     │     └─ follows _route, or reactive obstacle dodge
   │     ├─ advance()             great-circle step
   │     ├─ resolve()             push out of collision caps
   │     └─ parallel-transport forward vectors
   │
   ├─ explorer.update(dt, {time, speed, swimming, running, airborne, interacting})
   │     └─ ~40 joint rotations from blended sines
   │
   ├─ companion.update(dt, walker.normal, time)
   │     └─ its own Walker.update() + destination()
   │
   ├─ lighting.update(dt, walker.normal)
   │     ├─ auto: advance timeOfDay        │ held: solveTimeFor(normal, target)
   │     └─ set ambient / hemi / moon / sun colour from local daylight
   │
   ├─ bodies.update(sunDir, camera)        sun & moon billboards
   ├─ post.composite uniforms ◄─ night amount, bloom strength
   ├─ explorer.setLanternLit(night > 0.42) + point-light intensity
   │
   ├─ updateCamera(dt)                     globe or follow, exponential ease
   ├─ updateHud()                          nearby wonder, region, compass bearing
   ├─ checkWisps()                         proximity pickup
   │
   ├─ TW.core.tickAll(animTime)            86 registered animation callbacks
   ├─ world.update(animTime)               markers, wisps, clouds, wonder state
   ├─ confetti integration
   ├─ audio.update(dt, {speed, swimming, biome, night})
   │
   ├─ renderer.shadowMap.needsUpdate       on a time budget, not every frame
   ├─ post.render()                        scene → bloom → composite → screen
   ├─ adaptive quality check                wall-clock fps, two downgrade steps
   └─ telemetry publish                     every 0.25 s of simulation time
```

### 8.3 The most-called functions

`TW.core.mesh()` sits under every primitive; `TW.core.mat()` under every mesh.
`TW.walk.tangent()` and `TW.walk.arcLength()` are the two workhorses of motion —
`arcIsClear()` alone is called on the order of 10⁵ times while the navigation
graph is built.

## 11. Testing and verification

The game is graphical and stateful, so it is verified by **driving the real
build in a real browser** — no mocks.

### 11.1 How it is testable at all

Two deliberate hooks:

1. **`<output id="telemetry">`** — full runtime state as JSON, refreshed every
   0.25 s of simulation time.
2. **`TW.app`** — live handles to the renderer, scene, walker, world, lighting
   and the action functions.

> **A lesson worth recording.** The harness first read *everything* from
> telemetry and produced false failures. Telemetry refreshes on the **simulation**
> clock, which crawls under software rasterisation. Anything time-sensitive must
> read live state through `TW.app`; telemetry is for the human-facing summary and
> for checking that the channel itself works.

## 12. Performance engineering

### 12.1 The optimisation pass

Profiling after the first playable build:

| | Before | After | How |
|---|---|---|---|
| Meshes in scene | 926 | **437** | Instancing + sub-part baking |
| Draw calls (follow view) | 438 | **~200** | Same |
| Scene-graph groups | 1,527 husks | **353** | `pruneEmpty()` after baking |

Changes made:

- **Smoke and flames → `InstancedMesh`.** Puffs now fade by shrinking rather
  than by per-instance alpha, which instancing cannot express.
- **Animals baked per part.** Critters, fish, birds and butterflies had their
  static shells merged, leaving only genuinely animated joints separate. One
  critter went from ~8 meshes to 2.
- **Kelp rebuilt as a single swept ribbon** instead of a five-segment stack:
  26 fronds, 26 meshes.
- **Clouds → one `InstancedMesh`** for all 52 lumps.
- **Flower beds and the oasis baked**, saving ~150 meshes in one region.
- **`pruneEmpty()`** drops the placement scaffolding left behind by baking.

### 12.2 Runtime budgets

| Technique | Effect |
|---|---|
| Shadow map on a time budget | Re-rendered every 45 ms moving, 180 ms idle — not every frame |
| Bloom at half resolution | 5 fullscreen passes at ¼ the pixel cost |
| Pixel ratio cap | `min(devicePixelRatio, sqrt(2.3M / (w·h)))` — targets a pixel budget, not a ratio |
| Navigation graph cached | `WeakMap` on the collider array; built once, pre-warmed at load |
| Adaptive quality | 2 downgrade steps below 40 fps measured on the **wall** clock |

### 12.3 Where the triangles are

| | Triangles |
|---|---|
| Terrain shell | 33,620 |
| Sea shell | 24,500 |
| Props, characters, effects | ~211,600 |
| **Total in scene** | **269,719** |

## 13. Bugs found and fixed

Every one was caught by automated testing or by inspecting rendered output —
none were found by reading the code.

| # | Bug | Symptom | Root cause | Fix |
|---|---|---|---|---|
| 1 | **fps counter lied** | Always reported ~20 fps | Averaged the *clamped* `dt` (max 50 ms), so it could never report below 20 | Measure against `performance.now()` |
| 2 | **"Night" showed daylight** | Holding night left the sky bright | Phase pinned a clock time, not a local sun elevation | Solve `solveTimeFor(normal, target)` analytically each frame |
| 3 | **Black background** | CSS page gradient never visible | Composite wrote opaque alpha over the whole canvas | Carry scene coverage into premultiplied output alpha |
| 4 | **Game could open at night** | Spawn sometimes in darkness | `timeOfDay` initialised to a constant | `lighting.startAt(spawn, 0.66)` solves for morning at spawn |
| 5 | **Lava floated over slopes** | Flows hovered at the far end | One prop anchor spanning 6 m of a 20° slope | Rebuilt with `ctx.path()`, which drapes over terrain |
| 6 | **Crater props buried** | Rim rocks sank into the ground | Same single-anchor problem inside the crater | Flattened the crater floor in the elevation function |
| 7 | **Aurora flew off the planet** | Flat sheets floating in space | Built in a prop's local frame, ignoring curvature | Rebuilt in world space via `ctx.sky()`, bent around the globe |
| 8 | **First click stuttered** | ~76 ms hitch on the first auto-walk | Navigation graph built lazily | Pre-warm at load |
| 9 | **Sun drew through the planet** | Sky discs visible through terrain | `depthTest: false` on the billboards | Enabled depth testing |
| 10 | **Harness false negatives** | Tests failed on working features | Read telemetry, which runs on the simulation clock | Read live state via `TW.app` |

## 16. Extending the game

### Add a prop

```js
// in src/20-props.js
P.watchtower = function (parent, x, z, height) {
  var g = C.group(parent, x, 0, z);
  for (var s = -1; s <= 1; s += 2)
    for (var t = -1; t <= 1; t += 2)
      C.link(g, [s * 0.4, 0, t * 0.4], [s * 0.22, height, t * 0.22], 0.05, PAL.wood);
  C.box(g, 0, height, 0, 0.7, 0.06, 0.7, PAL.wood);
  P.gableRoof(g, 0.8, 0.8, height + 0.5, height + 0.9, PAL.roofRed);
  return g;
};
```

It bakes automatically. Use it from any region with
`ctx.place('mosswood', 2, -1, g => P.watchtower(g, 0, 0, 1.8))`.

### Add a region

1. Append an entry to `BIOMES` in `src/30-planet.js` — pick a `lat`/`lon` well
   clear of the others.
2. Add region-specific shaping in `regionElevation()` if wanted.
3. Push a builder onto `B.list` in a biome file.
4. Add a footstep profile to `GROUND` in `src/70-audio.js`.
5. Add a note to `NOTES` in `src/70-audio.js` if you go past eight regions.

### Add a wonder

```js
var thing = at(1, 2, function (g) {
  var mat = C.mat('#88ccff', { emissive: '#88ccff', emissiveIntensity: 0 });
  C.sphere(g, 0, 1, 0, 0.4, mat);
  var on = false;
  ctx.tick(function (t) {
    mat.emissiveIntensity = C.damp(mat.emissiveIntensity, on ? 2 : 0, 3, 1/60);
  });
  g.userData.activate = function () {
    on = !on;
    return on ? 'It hums awake.' : 'It settles.';
  };
});
ctx.wonder({ id: 'myregion-thing', biome: id, label: 'The thing',
             action: 'Wake the thing', description: '…',
             x: 1, z: 2, radius: 2.3, activate: thing.userData.activate });
```

The journal entry, marker, toast, chime and save handling are all automatic.

### Rules to respect

| Rule | Why |
|---|---|
| Never call `Math.random()` during generation | Use `ctx.rand()` — the world must be deterministic |
| Anything animated needs `C.dyn()` or `C.pivot()` | Otherwise `bake()` will merge it and freeze it |
| Long props need multiple `ctx.place()` anchors, or `ctx.path()` | One anchor over a slope hovers at the far end (bugs 5 and 6) |
| Register a collider for anything you should not walk through | `ctx.block(id, x, z, radius)` |
| Run `node build.mjs` after editing | Otherwise `dist/` goes stale |
